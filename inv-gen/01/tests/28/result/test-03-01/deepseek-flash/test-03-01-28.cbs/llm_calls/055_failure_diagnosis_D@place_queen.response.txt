[Failed Property]
preservation of i_53: assuming the invariant and loop condition before one iteration, the invariant must hold again after the loop body.

[Failure Cause]
The loop body of D@place_queen only updates `board[row*n+j]` and `j`; it does not modify `row` or `n`. Invariant i_53 is a pure arithmetic property over `row` and `n` and therefore is not invalidated by the body. The generated WP goal reduces to proving `i + i_1*n < n*row_0` from `0 <= i_1 < row_0`, `0 <= i < n`, and `0 <= row_0 < n`. This is a non-linear arithmetic goal. The prover cannot automatically derive the needed inequality chain. i_53 itself is not too strong; it is a valid arithmetic fact. The invariants of D@place_queen are not too weak—the old i_53 already implies the goal up to commutativity of multiplication. The missing bridge is the arithmetic fact `i + i_1*n < n + i_1*n = n*(i_1+1) <= n*row_0`, which uses `i < n`, `i_1+1 <= row_0`, and `n > 0`. Equivalently, the prover needs to instantiate the existing i_53 with `r=i_1`, `k=i` and use `n*i_1 = i_1*n`.

[Responsible Scope]
D@place_queen

[Refinement Direction]

The proof script should provide an explicit arithmetic hint or instantiation, e.g., assert the intermediate inequality `i + i_1*n < n*(i_1+1) <= n*row_0`, or instantiate i_53 to obtain `i + n*i_1 < n*row_0` and then use commutativity of multiplication. Ensure `1 <= n` (or `n > 0`) from `valid_board`/bounds is available to the arithmetic solver.
