[Failed Property]
preservation of i_12: assuming the invariant and loop condition before one iteration, the invariant must hold again after the loop body.

[Failure Cause]
The preservation obligation must re-establish `rows_solved(n, board, row)` after updating a cell in row `row`. Since `rows_solved(..., row)` only constrains rows `< row`, the update at `row*n+j` is outside the constrained prefix. Thus `i_12` is not too strong and is not semantically non-inductive. The failure is a missing frame/separation fact: the proof has `rows_solved` before the update and the new memory `Mint_0` as an update at `idx(n,row,j)`, but it does not expose that all cells in rows `< row` have unchanged addresses/values. The D@place_queen invariants are not too weak in principle for this goal; the missing ingredient is the arithmetic frame step that the current-row write cannot affect earlier rows.

[Responsible Scope]
D@place_queen

[Refinement Direction]
Use the supplied `rows_solved_frame` lemma with `row_limit = row`: prove that for all `r,c` with `0 <= r < row` and `0 <= c < n`, `idx(n,r,c) != idx(n,row,j)`; indeed `r*n+c < row*n <= row*n+j`. This shows the write in row `row` leaves all earlier rows unchanged, so the pre-update `rows_solved` transfers to the post-update state.
