[Failed Property]
preservation of i_12: assuming the invariant and loop condition before one iteration, the invariant must hold again after the loop body.

[Failure Cause]
The failed obligation tries to prove that appending the newly output vertex `v` preserves `output_edge_order` for the extended prefix of `result`. To do this, one must show that every predecessor `from` of `v` already occurs in `result` before the new position `count_0`. The inner loop `C@topo_sort` only establishes that such predecessors have `in_degree[from] == -1` (via invariants `i_18`/`i_21` when `can_output == 1`). It does not, by itself, relate `in_degree[from] == -1` to membership in the current `result` prefix. That bridge is supplied by `processed_vertices_are_output` (`i_13`): if `in_degree[from] == -1`, then `from` appears in `result[0..count_0-1]`. The WP proof fails because the available inner-loop postcondition does not carry this connection forward to the updated state `a_5`, and the outer-loop invariant `i_13` is not sufficient in the current context to close the gap without an explicit fact that the newly appended vertex `v` is not a predecessor of itself (or that all predecessors are already in `result`).

[Responsible Scope]
both

[Refinement Direction]
The missing logical fact is that when `can_output == 1` at the end of `C@topo_sort`, every predecessor of `v` is already processed (`in_degree == -1`) and therefore already appears in the existing `result` prefix before `count_0`. In particular, the needed bridge is the implication
`graph[from][v] == 1 ==> from appears in result[0..count_0-1]`
for all `from < n`, which follows from the conjunction of the inner-loop postcondition (`i_21` plus `u >= n`) and the outer-loop invariant `processed_vertices_are_output` (`i_13`). The verification needs to make this connection explicit, and also needs the fact that `v` itself is not a predecessor of `v` (or that `from != v` for any predecessor), so the update of `in_degree[v]` and `result[count_0]` does not disturb the earlier-positions condition.
